# 主报告规范

> **主报告 = 分析框架 + 财务基线**：回答"怎么分析这家公司、看什么、阈值多少、逻辑如何被证伪"；数据底座以**最新年报为基线**，后续实绩一律在 `财报跟踪/` 目录逐期更新，主报告**不随季度改写**。
>
> **本文把"研究流程"显式写进规范**：① 章节间有依赖关系，写作顺序≠章节顺序，存在天然串行主线与可并行素材；② 动笔前先做"前置定版"（时间轴 / 口径 / 数字核对表），消灭写作中期的返工；③ 明确哪些工作可拆给子代理并行、哪些必须主代理串行。写作格式与口径规则未变，只是把"先做什么后做什么"讲清楚。
>
> 本规范与 [财报跟踪规范.md](财报跟踪规范.md)、[README.md](README.md) 构成三件套：
> - **主报告规范（本文）**：主报告长什么样 + 用什么研究流程写出来；
> - [财报跟踪规范.md](财报跟踪规范.md)：跟踪文档长什么样（实例层，逐期更新）；
> - [README.md](README.md)：三件套索引 + 共用规则（文件夹结构、路径、工具、分工、格式）。

## 一、定位与更新纪律

**一句话：主报告是"尺子"，`财报跟踪/` 是"测量记录"——读数记在记录单上，不刻回尺子上。**

### 1. 两层分工：主报告装什么，跟踪装什么

| | 主报告（`<公司>.md`） | 财报跟踪（`财报跟踪/`） |
| --- | --- | --- |
| 装什么 | **分析框架**——怎么分析、看什么、阈值多少、逻辑如何被证伪；**财务基线**——最新年报的数字底座 | **逐期实绩**——每个报告期的实际读数，对照主报告阈值逐项验证 |
| 变化频率 | 一年动一次（年报重锚），框架变了才即时修订 | 每个报告期一个文件，滚动新增 |
| 红线 | 不出现"最新一期"季度数字 | 不发明主报告没有的变量 |

**核心纪律：主报告只含"框架 + 基线"，不含逐期实绩。** 要查最新数据，一律去 `财报跟踪/` 目录。

### 2. 主报告只允许三种情况改动

判断口诀：**先分清变的是"读数"还是"刻度"**——读数变了（这个季度毛利率是多少了）→ 只进跟踪层；刻度变了（警戒线本身该挪了）→ 才动主报告。

| 触发 | 动作 |
| --- | --- |
| ① **年报重锚** | 新年报披露后，财务基线（主要是三章）整体刷新为新年报数字 |
| ② **框架修订** | 核心逻辑、增长方向、阈值、估值基准变化时**即时**修订，不等年报 |
| ③ **季报不动主报告** | 一季报 / 中报 / 三季报披露后主报告一个字不改，实绩、验证全部进 `财报跟踪/` |

### 3. 头部标注：读者第一眼要知道"这份报告锚在哪"

主报告的数字冻结在年报时点，所以头部必须写清五件事：**写作基准日期 + 财务基线（<YYYY> 年报）+ 下一披露节点（报告期 + 预计日期）+ 指向 `财报跟踪/` 的链接（括号标注状态）+ 现价口径（含日期与盘中/收盘）**。头部只承载元信息，不放实绩；版式模板见 README"6.1 报告头部格式"。

### 4. 跟踪层只建"最新已披露报告期"，历史不回补

- **跟踪义务始终只有一项：为最新已披露的报告期建档。** 新报告期披露后再建下一个文件，旧文件留存作档案。

- **开始跟踪之前错过的报告期不回补**：如动笔时已是中报季、而一季报跟踪从未建过，则直接从中报建起——中报为上半年累计口径，已覆盖一季报信息，不必为"补齐时间线"回建一季报文件。

- 不回补报告期的数据从哪来：主报告基线表 + 该期披露数据本身（如主报告八章的三季持仓对比表已含各期数字），需要对比时在最新跟踪文件里附一句即可。

- 主报告头部链接只列"最新已披露（待建档）+ 未来待披露"的报告期，不列不回补的历史报告期。

### 5. 基线错位：动笔时季度已披露、基线还是旧年报怎么办

按三步处理：

1. **默认不搬**：季度实绩不进主报告正文（三章尤甚）——季度数字只出现在跟踪层。

2. **唯一例外——解释分歧时可在四章引用一次**：若需要某季度数据解释"为什么基准增速与一致预期不同"，写入"四、业绩预期"，以文字点明"该季度已披露、其变化主要系 XX 原因"——**XX 按这家公司的实际原因写**（可能是少数股东稀释、基数效应、一次性项目、费用节奏等，是什么写什么，不要套别的公司的归因），同时指向对应跟踪文件（未建档则注明"跟踪待补建"；历史报告期按第 4 条不回补）。

3. **罚则**：除上述例外与基线时点数据（须标注基线日期）外，主报告出现任何"最新一期"数字即违反分工。

## 二、研究流程总览

### 2.1 章节依赖关系

主报告十章不是平铺的，存在**强依赖串行主线**、**收口章**与**半独立章**三类：

```
主线（强依赖，必须按序、串行产出）：
三(财务基线) ─► 四(业绩预期 [g1,g2,g3]) ─► 五(估值 θ+情景) ─► 六(跟踪清单)
     ▲ 输出基线与阈值        ▲ 四章输出是五章输入      ▲ 依赖零章方向与四章验证窗口

收口章（最后写 / 回填）：
零(核心逻辑)：全篇的纲，但要等一~六章证据链成型才能定稿；
九(名词解释)：全篇回填，写作过程中边写边补新名词。

半独立章（素材就绪即可写，不阻塞主线，可并行准备素材）：
一(业务说明)   —— 依赖官方年报业务构成 + 分部数据表
二(宏观背景)   —— 依赖宏观库文档 + 年报行业章节
七(治理结构)   —— 依赖年报治理章节 + 股东数据
八(筹码方法)   —— 方法型章节，写方法 + 关注点，不依赖季度实绩
```

**推论**：
- 主线（三→四→五→六）必须串行——每一章的输出是下一章的输入，拆给多个代理各写一章会造成口径/数字冲突（见 2.4）；
- 零章是"阅读第一、写作最后"：可以先在动笔前起草方向草案，正文证据链成型后回填定稿；
- 半独立章的**素材准备**可与主线数据抓取并行（见 2.3），但**写作本身**建议仍由主代理完成（章节间口径需统一）。

### 2.2 推荐写作顺序（≠ 章节顺序）

```
第一阶段：前置定版（见 2.3 Phase 0）
第二阶段：素材就绪后按依赖推进
    半独立章（一/二/七/八）可先写 —— 素材齐了就写，不阻塞主线；
    主线按序写：三 → 四 → 五 → 六；
    收口：零（回填定稿）→ 九（补齐名词）。
```

写作是纯生成过程：一旦素材齐 + 定版完成，按上述顺序一口气产出，中途不需要等待外部返回（估值 CLI、api 抓取都在素材阶段完成）。

### 2.3 三阶段工作流

**Phase 0：前置定版（主代理，动笔前，一次性完成——消灭写作中期返工）**

1. **时间轴确认**：当前日期；最近已披露报告期及其与基线的差异（归母 vs 合并、单季 vs 累计）；下一披露节点（写入头部）；现价与口径（写入头部更新行）。
2. **口径定版**：全篇统一用哪套分部口径（分产品 or 分行业，或两者并存时写明换算关系）；归母 vs 合并口径的使用约定；有效税率、非经常项等"读数前提"清单。
3. **数字核对表**：列出所有将进正文的关键数字（收入/利润/毛利率/份额/现金流/阈值），每项标注数值、来源（api 字段 / 年报页码 / 一致预期日期）、口径。写作时逐项引用，不再临时查数。
4. **估值输入初定**：利润基数（基准年归母）、一致预期增速、θ 测定所需素材（净现比、资本开支、净现金）先收齐；估值表最后在五章阶段用 `tools/valuation.js` 生成。

**Phase 1：素材准备（可并行，见 2.4 分工）**

- 硬财务数据：`api/` 三表 + 主要指标 + 一致预期 + 股东结构，一次脚本抓齐落盘（写一次抓取脚本，全部接口轮询一遍）；
- 官方叙述内容：年报 PDF → `tools/pdf2text.js` 转文本 → **主代理 grep 关键段落**（管理层讨论 / 分部 / 经营计划 / 风险 / 分红 / 治理），按"素材卡"落盘；
- 网络补缺（仅当官方 PDF 未覆盖）：券商观点、行业动态、政策原文，注明来源与日期；
- 每个半独立章准备一张"素材卡"（业务构成要点 / 宏观状态 / 治理要素 / 筹码关注点），写作时直接引用。

**Phase 2：写作（主代理，按 2.2 顺序）+ 校验（可并行，见 2.4）**

- 写完后统一自检：数字核对表逐项回查（写作中口径是否与定版一致、数字是否有笔误）——格式与排版在写作时按 README"五、格式与排版"执行即可，验收阶段（成稿自检清单）不再逐条校验格式。

### 2.4 分工纪律：哪些可拆、哪些不可拆

| 任务 | 谁做 | 原因 |
| --- | --- | --- |
| 官方 PDF 叙述性内容整读/摘录 | **主代理**（grep 原文，不走子代理） | 可控、可中断、token 可预测；子代理整读 PDF 是 token 黑洞（AGENTS.md 铁律） |
| 章节**写作**（尤其主线三/四/五/六、收口零） | **主代理**（串行） | 章节间口径/阈值/增长判断必须同一头脑统一，拆章外包会造成冲突，合并成本 > 并行收益 |
| 找官方 PDF / 公告 URL | 子代理（≤2-3 个搜索，禁下载大文件） | 主代理低成本做不到（外部检索） |
| 补 2-3 个特定小事实（政策日期、券商观点原文等） | 子代理（每主题 ≤2 搜索，先交已有结果） | 同上 |
| 写作后**数字/口径校对** | 可派子代理（给核对表 + 正文，逐条查） | 独立校验，可与主代理写后半部分并行 |
| 硬财务数据抓取 | 主代理脚本（api/ 封装） | 结构化接口，一次轮询即可 |

> 原则：**子代理只做"主代理低成本做不到"或"可独立验证"的事**。禁止派"帮我写一份 XX 汇编/研究总结"型大代理；禁止子代理下载/整读 PDF。子代理结果必须精简落盘（表格/要点 + 来源 URL），不把冗长正文带进主上下文。

## 四、章节骨架与写作指引

### 写作总原则（动笔前先读）

本章以下各节的"建议结构""举例""括号说明"是**思考方向与示意，不是固定模板**——具体公司要按它的实际情况调整写法，不要照抄示例句式或示例内容：

- **括号里的"常见形态 / 例如 / 通常"只是帮你打开思路的举例**（如竞争格局、增长方向、读数前提、传导路径），**不是必须出现的条目**：这家公司没有大额一次性项目、没有税率失真，就不要硬写一段"读数口径"；这家公司的对手不是"巨头 + 小厂"两分结构，就按实际写它的对手；
- **判断性结论（对手是谁、增长靠什么、护城河在哪）必须基于这家公司的实际证据**——规范给的是"该想什么、往哪个方向想"，不是"该怎么写、写什么词"；写作时先问自己"这家公司的事实是什么"，再落笔，而不是先套格式再填词；
- **真正要照做的是结构性硬规则**，这类规则不因公司而异，必须严格执行：固定小节标题（`### 要点速览`）、章节分工纪律（业务构成不写经营数字、宏观不下公司判断）、每个增长方向必写"现实约束"、估值纪律（θ 测定后固定、情景表只用 `tools/valuation.js` 生成、过渡期统一 3 年）等；
- **拿不准"这条是规定还是举例"时，按举例处理**：结合公司实际自由发挥，宁可少套一层格式，也不要机械照搬造成内容失真。

### 章节速览

| 章节 | 一句话目的 | 依赖 | 写作阶段 |
| --- | --- | --- | --- |
| 零、核心逻辑 | 全篇的纲：可证伪的投资判断 + 增长方向 + 护城河 | 一~六章证据链 | 收口（最后定稿） |
| 一、业务说明 | 业务地图：卖什么、钱从哪来（客观描述，不下判断） | 年报业务构成 + 分部表 | 半独立（可先写） |
| 二、宏观背景 | 宏观顺风还是逆风、通过什么路径影响盈利与估值 | 宏观库 + 年报行业章节 | 半独立（可先写） |
| 三、财务报表分析（财务基线） | 从最新年报读出经营本质 + 关键项目跟踪阈值 | api 三表 + 年报 | 主线第一步 |
| 四、业绩预期（基准情景） | 输出基准利润路径 [g1,g2,g3] + 机构预期 + 管理层观点 | 三章输出 | 主线第二步 |
| 五、估值（估值框架） | 贵不贵、买不买：θ 测定 + 只围绕利润假设的情景 | 四章 [g1,g2,g3] | 主线第三步 |
| 六、跟踪清单 | 定义跟踪什么：重点数据 / 催化剂 / 风险 | 零章方向 + 四章窗口 | 主线第四步 |
| 七、治理结构 | 谁说了算、利益是否与股东一致 | 年报治理章节 + 股东数据 | 半独立（可先写） |
| 八、流通股东变化（筹码方法） | 筹码在谁手里：方法 + 关注点 | holderData 接口 | 半独立（可先写） |

### 零、核心逻辑

> 全篇的"纲"，阅读排第一、写作排最后。本章只做结论性判断，不展开数据论证；每个判断在后续章节都有对应证据，读者读完本章即掌握全文骨架。

**开篇固定以"要点速览"小结引导（本章第一小节）**：把全篇判断压成**可证伪**的要点（利润靠什么释放、增长靠什么驱动、护城河在哪、估值/风险位置），**不要写超长的"一句话核心逻辑"堆叠段**。写法：

- **小节标题**：`### 要点速览`（与章内其他小节同级）；
- **第一段（结论要点）**：每类判断各一句、直接下结论——利润从哪来（不靠什么）、增长靠哪几个方向、护城河在哪、现价/估值结论。**用自己的话写这家公司的事实判断，不套模板句式**（例如估值结论不需要写成"现价 XX 倍 PE，隐含增速 XX，买的是 XX 期权"这样的固定句法——按这家公司估值最要紧的那句话自然表达即可，可能讲的是 PE、可能是分部估值、可能是赔率，是什么就说什么）。数字只给锚点值，论证留给后续小节；
- **第二段（读数口径提醒，按需）**：只有在这家公司确实存在"读利润表/估值前必须先知道"的前提时才写（常见可能包括：首次盈利是低基数、报表口径差异、大额一次性或非现金项、税率失真、少数股东稀释等——**按这家公司实际情况判断有无，没有就整段不写**，不要为了凑结构硬列几条）；有则用自然引导另起一段（如"先记一个读数口径：……"），不堆进结论段；
- **段落收尾**：一句导航——证据链见以下各节、催化剂与阈值见"六、跟踪清单"，并链向 `财报跟踪/`。

**建议结构**（要点速览之后）：

- **从业务场景看增长预期**：每个方向回答"钱从哪里来、往哪里扩、在哪里卖"。**方向的数量与切分维度按这家公司实际定**：多数公司 3—4 个并列方向，但业务单一的公司可能只有 1—2 个方向，业务多元或有明确主线的公司可能按层层递进组织而不是并列——**切分维度（业务线 / 内外需 / 商业模式等）也以最能讲清这家公司增长来源的方式为准，不要为了凑齐格式硬切**。每个方向写四件套：
  - **逻辑**：为什么这个方向能带来增长（一句话本质）；
  - **驱动力**：现实里哪些因素正在推动它发生（列 2—3 条，写清"政策 / 技术 / 需求"的具体机制，不堆概念；**驱动因素按这家公司实际写，没有政策驱动就不要编政策驱动**）；
  - **验证指标**：看什么指标、阈值是多少、跟踪频率与来源——这是框架的"仪表盘"，**不过期**；如需基线数字佐证，标注基线日期，最新值一律到 `财报跟踪/` 查；
  - **现实约束**：什么条件下它会证伪——**必写**，防止只讲乐观面；约束同样要具体到这家公司，不写放之四海皆准的套话。
  - 有内外需之分的公司，通常单独做一个"地域"方向，把海外增量的确定性与内需企稳的成色（政策托底 / 低基数修复 / 内生结构性，三者可持续性天差地别）拆开看；**没有内外需之分（纯内需或纯外销）的公司，不要硬造一个地域方向**。
- **护城河**：先**点明对手是谁——按这家公司的实际竞争格局判断，不要套固定句式**（有的公司对手是外资巨头，有的是国产小厂混战，有的是"巨头 + 小厂"上下夹击，也可能只有一类对手或没有直接对手——写清楚对这家公司真实构成威胁的是谁即可）。点明对手后，**给护城河打 10 分制评分——先给分数结论、再给依据，不用"强 / 中 / 弱"三档做结论**。**成稿布局固定为四段，证据一律收进评分表，不在表外重复展开**：
  - **① 总分结论**：X / 10 + 一句定位（如"8/10：第一梯队强护城河，未到垄断级"）+ **一行判分刻度**（9—10 垄断级 / 7—8 强 / 5—6 中等 / ≤4 弱）——数字是结论，文字只帮读者定位；刻度只写一行，不逐档展开；
  - **② 评分表（一表打尽，证据的唯一存放处）**：维度（可带权重）| 评分 | 防的是谁（为什么学不来）| 依据与扣分点——逐维度证据**全部收在表内行**："防的是谁"须对应开头点出的实际对手，写不出对应对手说明该维度站不住；"为什么学不来"落到商业模式 / 组织 / 网络效应等本质差异，不写"这不是能力问题"式空话。**不再在表外另列"壁垒一 / 壁垒二……"长段**（同一事实在表里出现一次即可）；表末可加"加权总分"行（写清算式，如 0.30×9 + 0.25×8 + … = 8.1 ≈ 8，四舍五入后与 ① 结论一致）；
  - **③ 一句话定位**：把"为什么不是更高分 / 为什么不是更低分"压成**一段**（不是两段）——上界一句（离垄断级差在哪：技术代际未证伪 / 定价权非垄断 / 大客户话语权等，按实际写），下界一句（够不上"中等"的证据：逆风检验 / 壁垒互强化 / 对手学不来的点）；
  - **④ 下调条件**：写出"什么事实持续发生 → 分数下调到几"（建议"持续两个报告期"触发），验证进 `财报跟踪/` 记录证据——评分必须可证伪，写不出下调条件的评分是空话。
  - **判分刻度参照**（元规则，供作者判分时对照，**不要整表抄进研报正文**——研报里只保留 ① 内的一行刻度）：

| 档位 | 刻度定义（硬规则） | 什么样的公司判在这档（判分要点） | 达不到上一档 / 判不进本档的常见原因（引导，按实际取舍） |
| --- | --- | --- | --- |
| 9—10 垄断级 | 无可替代对手、有定价权 | 格局接近单极或稳定双寡头：客户没有第二个同等选项；定价权有实证（逆周期 / 成本上涨时仍能提价或稳毛利，不靠让利保份额），且提价不引发客户自研或监管干预 | 多数"看起来垄断"的公司有隐性替代：技术代际风险、客户垂直整合自研、政策 / 集采限价（有市场地位无定价权）、渠道被新范式颠覆——**有垄断之名无提价之实，落到 7-8** |
| 7—8 强护城河 | 多维壁垒叠加且经受过逆风检验，但存在可证伪的代际 / 价格风险 | 壁垒至少两三层互相支撑（品牌 / 网络效应 / 转换成本 / 成本优势等组合，单一维度打不穿）；经受过一轮完整逆风检验（行业下行或价格战时份额与利润率未实质受损）；风险可明确命名（"被 XX 路线替代""XX 客户降价"），不是模糊担忧 | 达不到 9-10：①存在规模相当的对手，谁也提不了垄断价；②定价权有天花板（替代品价格上限、监管上限、大客户议价）；③逆风检验时间不够长——只在顺周期被验证过，严格说只能算 7 甚至 6 |
| 5—6 中等 | 单一或薄壁垒，靠行业景气 | 有一个真实的单维壁垒（成本领先 / 渠道覆盖 / 资质牌照 / 局部客户关系之一），单点上有优势；利润弹性高度依赖行业β，景气时盈利不错 | 达不到 7-8：①壁垒单维——对手在**同一维度**上投入即可逼近，无需绕路；②行业下行时壁垒护不住盈利；③把行业"景气"误当公司"护城河"——β 拿走时分辨不出是公司强还是行业强 |
| ≤4 弱 | 弱 | 产品 / 服务接近同质化：转换成本≈0、比价即换、竞争唯一武器是价格；无复利来源 | 判不进 5-6：①连单维壁垒都不成立；②现金流与利润完全跟随行业与价格波动；③识别出 4 分以下并因此放弃，比把每家公司论证成 8 分更有用 |

  - **判分刻度使用纪律**：①判分要基于证据不是感觉——定价权看"提价是否成功过"，逆风检验看"下行期毛利率 / 份额是否守住"，替代风险看"客户是否真有第二个选项"，给不出证据的维度不算分；②刻度是**给结论定档的自检尺**（写完 ③"一句话定位"后对照刻度确认分数落档），不是再写一遍刻度描述；③明确识别出 ≤4 分并放弃，防止护城河写作变成给任何公司都找优势的赞美练习。
  - **打分纪律**：每个维度的"依据 / 扣分点"必须用这家公司的数字或事实支撑（份额、毛利率、客户集中度、研发投入、现金流等），不凭感觉打分；评分评的是结构不是单季，不随季报重评，下调条件触发才修订（见 ④）。
- **核心跟踪变量（不在零章放表）**：零章**不再单列"核心跟踪变量"表格**——它与"六、跟踪清单"的重点数据重复；增长方向四件套里的"验证指标"（各方向的仪表盘）已够零章使用。完整行级清单（跟踪项 / 指标 / 阈值 / 频率 / 来源）统一放在"六、跟踪清单 → 1. 重点数据"，零章只需在要点速览用一句导航指向六章。

> **写作提示**：零章可先起草"方向草案"（增长方向 + 阈值），用于指导后续章节的素材收集口径；正文证据链成型后回填完整版本，避免先写零章、后写正文导致"纲"与"证"脱节。

### 一、业务说明

**客观描述**：公司卖什么、钱从哪来、靠什么赚钱。**不下判断**，判断留给"零、核心逻辑"。

**素材卡**：年报"管理层讨论与分析"开头的业务构成 + 分部经营数据表 + 年报"业务特点"相关段落。**素材阶段一次 grep 齐**，关键词按年报实际章节标题取（常见为：主要业务 / 营业收入构成 / 分行业 / 分产品 / 分地区 / 经营模式，以这份年报实际用词为准，找不到就换词，不必照搬清单）。

**建议结构**：业务构成（做什么）→ 分部经营数据（表 + 经营状况解读）→ 业务特点。

- **业务构成只讲"这块业务具体是做什么的"**——服务内容、技术/工艺/平台、交付物、下游客户是谁、与下游的分工边界、在产业链或商业模式中的位置等**能讲清这家公司业务本质的要素，按实际需要取舍**（不是每家公司都正好有这些要素，讲清"它是做什么的、怎么赚钱"即可）；**经营状况（收入、规模、增速、毛利率）一律放到"分部经营数据"下解释**——两者不互相重复，业务构成里出现经营数字即属越界。
- **分部经营数据**：收入、占比、同比增速、毛利率的汇总表（+ 区域表），表格之下配**经营状况解读**——每条业务线讲清"数字背后发生了什么"：增速分化的原因、毛利率变动的**真实归因**（成本红利、结构升级、汇率、一次性因素——是哪一种就写哪一种，不预设答案）、区域集中度含义、口径与隐藏细节（例如某板块下滑，先判断是主动收缩还是需求崩塌，再决定解读方向——这只是提示思考方向，实际原因以年报说明与数据为准）。表格负责给数字，解读负责解释数字。
- **业务特点**：提炼每条业务线的**结构性**特点（商业模式、增长质量、战略含义），为"三、财务报表分析"与核心逻辑埋伏笔；不再重复分部经营数据里的经营数字。

体量小、业务单一的公司可以合并业务线、简化分部表——不强制凑满四个板块。

### 二、宏观背景

评估该股票所处的宏观环境——经济周期位置、利率与流动性、汇率、政策与产业环境，回答"宏观是顺风还是逆风、通过什么路径影响公司盈利与估值"。**只做环境评估，不下公司判断**。

**素材卡**：`doc/知识库/宏观/` 文档（总览 + 与公司关联度最高的 2-4 份月度文档）+ 年报"行业情况"章节。**行业景气的口径描述以年报原文为准**（年报里怎么写该行业当年的市场增速/需求结构，就引用什么，不要替它发明口径）。

**建议结构**（按需取舍，不强制五小节齐全）：宏观周期定位 → 利率与流动性 → 汇率与外部环境 → 政策与产业环境 → 宏观到公司的传导（表 + 总结段）。**宏观变量里哪些与这家公司真的相关，才展开哪几节**：一家纯内需、无外汇敞口、对利率不敏感的公司，利率/汇率小节可以整节不写；末尾的"宏观到公司的传导"是本章的落点，必须写清"宏观通过什么路径影响这家公司的盈利与估值"。

- 写"**传导路径 + 一句话当前定位**"：传导路径相对稳定，**按这家公司真实的经营逻辑写，不套用其他公司的例子**（例如"利率 → 估值底座"几乎对所有公司成立，但"财政支出 → 招标"只对政府/项目采购型公司成立、"汇率 → 汇兑损益"只对有外汇敞口的公司成立——先想清楚这家公司靠什么宏观变量吃饭，再写路径）；当前状态随**年报重锚**刷新，宏观重大变化时即时修订。
- 传导表：宏观变量 | 当前状态 | 传导路径 | 对公司的影响 | 跟踪指标——**表格里只放与这家公司真实相关的宏观变量**（关联弱的不塞进表，正文一句带过即可）。末尾一段总结：宏观整体顺风 / 逆风 / 中性；最大的宏观变量是什么；它对"零、核心逻辑"里哪条假设影响最大、证伪阈值是什么。
- 与公司关联弱的宏观变量可以略写，不必面面俱到——重点写影响最大的 2—4 条路径。

### 三、财务报表分析（财务基线）

从数字读出经营本质。本章 = **财务基线（最新年报锚点）**：只分析最新年报，不随季度改写；季度变化在 `财报跟踪/` 逐期更新。

**素材卡**：`api/` 三表 + 主要财务指标（年报口径，近 3-5 年趋势，抓取备用；表内列示期数见 README"6.2"）+ 年报费用/减值/现金流相关解读段落。**一次脚本抓齐全部接口**（见 2.3 Phase 1），先落盘再写作。

**建议结构**（可按公司情况调整；**重点关注大额/重点项目，其余按需取舍**）：

1. **经营相关数据**：收入规模与结构（分业务/产品/地区）、订单与合同负债、市占率、产能与人员、经营效率等——**这些是"往哪些方向看"的提示，按这家公司实际有信息量的项展开**，不需要逐项都写。
2. **利润表**：收入 → 成本 → 毛利 → 费用率 → 利润。**毛利率变动要写出真实归因**——先想清楚这家公司毛利率为什么变（可能是成本红利、产品结构升级、价格竞争、汇率、产能利用率等，也可能是多因素叠加），再按实际归因写，**不要预设成"成本红利 vs 结构升级"二选一，也不要套用别的公司的归因**；归因的持续性（一次性 vs 结构性）是判断重点。大额费用项目（销售/研发/财务/资产减值等）单独说明。
3. **资产负债表**：按余额与占比找**这家公司真正的大额科目**（提示：货币资金与理财、应收账款、存货、固定资产/在建、商誉、有息负债等都可能大，但哪几个大、哪几个值得写，由实际数字决定——余额占比不高的科目不要为了凑清单硬写），每项写"数字是什么 + 说明什么"；关注质量（应收/存货是否恶化、债务结构是否优化）。
4. **现金流量表**：经营/投资/筹资三大活动 + 净现比；经营现金流与净利润的匹配度（利润质量），**大额流向按实际看是什么**（可能是并购、分红、理财、扩产、募资——是什么写什么，不要三种都列）。

- **三章表格格式**（要点表 → 解读列入表 → 独立"同比"列（+红 -绿）→ 表后整表判断；含"成稿样板"）：统一见 README"六、主报告版式规则 → 6.2 财务报表分析表格细则与成稿样板"，本节只给分析要点，不再重复格式规则。

- **关键项目跟踪阈值**：列出**这家公司需要逐期盯的科目**与阈值、数据来源，作为 `财报跟踪/` 逐项更新的基线参照。盯什么由三、四章的分析自然得出——**通常是与核心逻辑直接相关、会先于业绩变化的科目**（可能是毛利率、合同负债、订单、商誉、经营现金流等，**按这家公司的业务特征挑，不要固定抄一组科目**；业务上不需要盯的科目就不列）。
- 新年报披露后，本章整体刷新为新年报（年报重锚）。

### 四、业绩预期（基准情景）

给出未来 1—3 年的业绩基准、增长驱动、利润拆分预测与机构一致预期。本章输出**基准利润路径 [g1,g2,g3]**——这是估值的输入，主观判断集中在这里。

**素材卡**：上年实际（三章基线）+ 管理层经营目标（年报"经营计划"原文）+ 一致预期（`api/orgForecast.js`）+ 管理层在公开场合的观点（注明时间与场合）。

**建议结构**：业绩基准 → 增长驱动 → 利润拆分预测（拆分口径 / 利润增速预期怎么拆）→ 机构预测参考（基线时点）→ 管理层观点。

- **业绩基准**：上年实际 + 公司当年经营目标（收入 / 利润口径）。
- **增长驱动**：按重要性列出未来几年的增长驱动，每条写清机制与验证指标。
- **利润拆分预测**：把增长驱动翻译成"未来三年利润从哪来、按什么口径拆、增速怎么推"。拆分维度：①按业务分部（各板块利润基数、增速假设、增量贡献）——通常必做，业务单一、拆分无增量信息的可整体口径并注明；②按利润性质（经常性 vs 一次性）——仅存在大额一次性项目时使用；③按内外需 / 产品结构——适用于收入结构二元分化的公司。写清口径规则（哪些业务计入 / 不计入、一次性项目单独处理），并**标出主观判断最强的一步与可证伪的跟踪指标**。
- **机构预测参考**：基线时点的一致预期（表格：年份 / 预测 EPS / 对应净利 / 增速 / 基线 PE），与拆分结果交叉验证；与一致预期的**逐期对照移入财报跟踪**。若基准与一致预期分歧明显，写明分歧点与按保守/乐观处理的理由（官方口径优先，券商预期只作参考——见 README"分析观点纪律"）。
- **管理层观点**：管理层在投资者交流会、业绩说明会等公开场合发表的观点——官方经营目标与指引、对市场关切的回应、战略方向表态。写清**时间与场合**；**若确实存在市场担忧且管理层有回应，用"市场担忧 vs 管理层回应"表格记录；没有形成担忧-回应结构的场合，直接写管理层表态即可，不要硬凑成表格**。新表态的验证在 `财报跟踪/` 的"业绩预期（最新）"节更新。

### 五、估值（估值框架）

把前文所有定性判断翻译成"贵不贵、买不买"。**核心纪律：估值只由利润路径（[g1, g2, g3]）与兑现系数 θ 决定；经营风险全部计入利润预测，不在 θ 上打折。** 统一采用 `doc/估值理论/估值模型.md`（R = rf + 5.5%、g∞ ≈ 2.33%、**过渡期统一 3 年**——风险补偿，不调整），计算用 `tools/valuation.js`。

**建议结构**：

```
### 1. 估值测算
#### <公司>的 θ 测定
#### 基于利润路径测算估值      # 增速情景表（固定 θ）
### 2. 估值结论
#### 模型结论
### 3. 验证窗口
```

- **θ 测定**：根据公司的现金转化画像一次测定 θ₀ / θₓ——轻资产还是重营运资本、净现比、账上净现金，给出基准 θ（θ = 0.15θ₀ + 0.85θₓ）。**测定后固定，不再做 θ 分档情景**——θ 只反映利润兑现质量，不做高估/低估分档。θ 所需的净现比、资本开支、净现金等素材在 Phase 0 收齐，避免写到五章再回头翻表。
- **基于利润路径测算估值**：**估值情景只围绕利润假设**——固定 θ，做不同增速假设 [g1,g2,g3] 下的情景（悲观 / 保守 / 中性 / 基准 / 乐观），每档给出利润路径、内在 PE、股价、相对现价的涨跌幅。情景表**必须用 `tools/valuation.js` CLI 生成**（`node tools/valuation.js <spec.json>`），数字与程序输出一致；表内带 +/− 符号的数值（如"相对现价"涨跌幅列）**按 A 股惯例着色：+ 红、- 绿**（与"三、财务报表分析"的同比着色约定一致），颜色仅为渲染标注、不改动数值——允许对 CLI 输出做纯着色处理后粘贴，并注明"数值与 CLI 输出一致"。**关键读数**：现价落在哪个增速情景附近，反推市场隐含的利润路径。
  - **情景行单调性提示**：情景增速 [g1,g2,g3] 各行之间应大致单调递增（悲观 < 保守 < … < 乐观），尤其第三年 g3 决定过渡期起点，若"乐观"行的 g3 低于"一致预期"行，会出现估值排序反直觉的结果——生成表后人工检查一次排序。
- **模型结论——用表呈现**：表格：结论维度 | 结论 | 依据 / 触发条件。结论维度按这家公司估值里最要紧的几点取舍（不必五条齐全），常见为：贵不贵（低估 / 合理 / 高估 + **分歧在哪一段**——近三年利润还是终值假设）、赔率结构（下行 / 上行空间，用数字，带 ± 符号的按 +红 -绿 着色）、买入的本质（买的是什么）、核心张力（市场假设 vs 本报告基准假设 + 验证信号）、安全边际（净现金 / 分红承诺 / 现金流质量等**实际**确定性支撑，没有就不写，不套清单）。
- **验证窗口**：列出未来几个关键时点（季报、全年业绩、事件进展），各自验证哪条逻辑——优先验证"四、业绩预期"里利润拆分主观假设最强的变量。

### 六、跟踪清单

定义跟踪什么（**写一次**）：重点数据、催化剂、风险。本章是 `财报跟踪/` 目录的**唯一变量来源**——跟踪只验证这里的项目，不发明新变量（除非出现了新的必须关注的变量，再更新这里）；最新状态与验证按财报节点在跟踪中更新，本章不随季度滚动。

**建议结构**：① 重点数据（表）→ ② 催化剂（直接描述）→ ③ 风险（高 → 低）。

- **1. 重点数据（逐期对照的唯一行级清单）**：一张总表——跟踪项 | 看什么指标 | 阈值 | 跟踪频率 | 来源。行数与这家公司要盯的变量一致（通常 6—9 项：量/份额、毛利率、储能等第二曲线出货、海外、合同负债、经营现金流、单位盈利、新业务等，按实际取舍）。**阈值、频率、来源全文只在这里出现一次**；零章不再重复放同类表。
- **2. 催化剂（什么时点、看什么会改变市场定价）——用表呈现**：不是独立事件清单，而是同一批已验证逻辑的不同触发点。**表格：触发信号 | 看什么（指标引用"1. 重点数据"对应行）| 验证时点 | 成立 / 不成立的含义**——行数与该公司的增长方向数对应（动力 / 储能 / 海外 / 盈利等，按实际），另可视情况补"股东回报事件""隐藏的免费期权（已入报表但不被单独估值）"两行；**用直接语言、不用比喻或黑话**；表下用一行注写跟踪节奏（必看节点：季报/中报/年报 + 行业数据频度：月度装车 / SNE / 周度价格等）。
- **3. 风险——用表呈现**：**评级单列一列**，**表格：评级（高 / 中高 / 中 / 中低等）| 风险 | 如果发生 → 会造成 | 与估值 / 核心逻辑的对应**，行按评级高 → 低排序；"如果发生"写具体可观察的触发情景，"会造成"写后果并指向对应估值情景或跟踪变量，不写空话；风险是核心逻辑的逆命题。评级列文字短、易被挤压——撑宽与居中的实现（内联样式 / `:---:` 回退）属纯排版，统一见 README"表格中短分类列撑宽"。

### 七、治理结构

回答"谁说了算、利益是否与股东一致、有无减持 / 质押隐忧"。信息表 + 一段定性评价。

**素材卡**：年报"公司治理"与"股东和实际控制人"章节（前十大股东、实控人及一致行动人、质押）、`api/holderData.js`（`getTopHolders`）、公司大事（增减持/质押公告）。

- 信息表：股权结构、实控人、董事长 / 总经理、重要股东、总股本、董事会构成、累计分红、员工人数等。
- 定性评价：**按这家公司实际写治理特征**——是谁在主导（可能是创始人、职业经理人、国资、外资股东，写法不同），内部人信号（增减持、质押）有没有、意味着什么，分红政策与股东回报取向，接班与合规等长期观察点（**哪些与这家公司相关就写哪些，与它无关的观察点不要硬凑**）。相对静态，随重大变化修订。

### 八、流通股东变化（筹码方法）

回答"筹码在谁手里、聪明钱在进出什么"。本章 = **一张表 + 一段总结分析**（不设观察维度、方法等小节的逐条展开）：

- **表：最近三个报告期末前十大流通股东持仓对比表**——列：股东 | 2025-12-31（基准）| 2026-03-31 | 较上期 | 2026-06-30 | 较上期 | 变化要点。**持股比例列与其"较上期"变动列分列呈现**："较上期" = 该期末比例相对上一报告期末的**增幅（%）**，即 (本期比例 − 上期比例) ÷ 上期比例，总股本变动小时即持股量环比增幅；+红 -绿只表符号，变动不足 0.05% 记"—"，首列为基准期不标；含新进 / 跌出标注；表注写口径（占期末总股本、各期对比基准、季度为已披露数据）。

- **表后写总结分析**：按筹码主线分 3—4 点（**每条独立成段、短加粗引导词**，不写成长段落）——① 边际资金方向：谁在买、谁在卖（外资 / 北向、H 股、内部人减持等），是否与基本面共振；② 结构变化：被动资金进出、股东户数集中 / 分散（聪明钱 vs 散户）；③ 使用纪律一句：筹码是验证信号不是选股依据，正共振才可信，反向（外资增持但基本面恶化）以基本面为准。

- **其余逐期明细（股东户数趋势、大宗交易、质押解押等）仍进 `财报跟踪/` 对应报告期**，主报告只放这一张三季对比表 + 总结分析。
