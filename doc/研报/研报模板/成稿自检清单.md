# 成稿自检清单

> **用途**：主报告 / 财报跟踪成稿后的机械验收，也是**校对子代理的执行清单**（prompt 模板附文末）。每条必须能对着一篇 md 独立判定 ✅ / ⚠️ / ❌——主观判断质量（归因、假设、观点是否合理）不在校对范围。清单是"索引 + 判定标准"，规则正文以锚点所指文件为准；改规范时同步改本清单。

## G 全局排版（锚：[README.md](README.md) "五、格式与排版"）

- G1 分点条目（`-` / ①② / 编号）之间留空行，正文、表注、指引全适用
- G2 带 ± 符号的数值（同比 / 增速 / 涨跌幅 / 增减额）全部着色：+ 红 `#d02020`、- 绿 `#0f7a33`，全文色值一致
- G3 数值列纯数字、右对齐、加千分位
- G4 短分类列（如风险"评级"）已撑宽居中（内联样式或 `:---:`）
- G5 章节内小节标题用 `### 1. / 2. …` 编号
- G6 跨目录引用一律项目根相对路径文本（`doc/…`），无 `../../../` 相对链

## H 头部（锚：主报告规范 §一.3 / §一.4；[README.md](README.md) 6.1）

- H1 五要素齐：写作基准日期 ／ 财务基线（YYYY 年报）／ 下一披露节点（报告期 + 约日期）／ 跟踪链接（括号标注状态）／ 现价（含日期与"盘中/收盘"）
- H2 跟踪链接只列"最新已披露（待建档）+ 待披露"，不列不回补的历史报告期
- H3 报告更新行含数据来源清单（api 接口名 + 一致预期日期）

## C 逐章（编号 = 报告章节；锚：主报告规范 §四）

- C0-1 开篇固定 `### 要点速览`，且为本章第一小节
- C0-2 四类判断各一句（利润从哪来 / 增长靠什么 / 护城河在哪 / 估值结论），数字只给锚点值
- C0-3 无"核心跟踪变量"表；有一句导航指向六章
- C0-4 每个增长方向四件套齐全，**现实约束不得缺**；驱动因素贴合公司实际，无硬造
- C0-5 护城河五件齐：对手是谁 → 总分（X/10 + 一行判分刻度）→ 评分表（防的是谁 / 依据扣分点，含加权算式）→ 一句话定位（一段）→ 下调条件（"持续两个报告期"触发）；评分表外无壁垒长段；判分刻度大表未抄入正文
- C1-1 业务构成无经营数字（收入 / 规模 / 增速 / 毛利率）
- C1-2 分部表（分产品 / 分地区）+ 表下经营状况解读；业务特点不重复分部数字
- C2-1 只做环境评估不下公司判断；传导表只含与该公司真实相关的变量
- C2-2 末段总结含：最大宏观变量 + 对零章哪条假设影响最大 + 证伪阈值
- C2-3 行业景气口径以年报原文为准（注明引用口径）
- C3-1 章首口径注：同比口径、着色仅表符号、负值科目净额增减
- C3-2 每张要点表：表题三要素（期数 / 单位 / 口径）+ 五列（项目｜上期｜本期｜同比｜解读）+ 起始列不标同比
- C3-3 同比列只写"符号 + 数字"（% / pp / 天 / 亿元净额），无文字描述
- C3-4 每张要点表后有"这张表告诉我们……"整表判断
- C3-5 自算科目的项目名标注"（自算）"
- C3-6 末节"关键项目跟踪阈值"表存在（科目｜盯什么｜阈值｜来源）
- C4-1 五小节齐：业绩基准 / 增长驱动 / 利润拆分预测 / 机构预测参考 / 管理层观点
- C4-2 机构预测表五列：年份｜预测 EPS｜**对应净利**｜增速｜基线 PE
- C4-3 标出主观最强假设 + 可证伪跟踪指标
- C4-4 管理层观点注明时间与场合；无"担忧-回应"结构时未硬凑表格
- C4-5 季度实绩仅出现于解释基准增速的必要处（主报告规范 §一.5 豁免），且指向对应跟踪文件
- C5-1 结构与规范一致：θ 测定 → 增速情景表 → 模型结论 → 验证窗口
- C5-2 模型参数：R = rf + 5.5%、g∞ ≈ 2.33%、过渡期 3 年；θ = 0.15θ₀ + 0.85θₓ，测定后固定，无 θ 分档情景
- C5-3 情景表由 `tools/valuation.js` 生成并注明"数值与 CLI 输出一致"；情景行增速单调递增
- C5-4 关键读数：现价落在哪个情景 + 反推市场隐含利润路径
- C5-5 模型结论用表（维度｜结论｜依据/触发条件）；验证窗口优先验证最强假设
- C6-1 三节齐：重点数据（5 列）／ 催化剂（4 列 + 指标引用重点数据行号 + 表下节奏注）／ 风险（4 列 + 评级撑宽 + 高→低排序）
- C6-2 阈值 / 频率 / 来源只在六章出现一次；零章无同类表
- C7-1 信息表 + 定性评价，按公司实际写观察点，不硬凑
- C8-1 三期末前十大流通股东对比表：列式固定；较上期 = (本期 − 上期) ÷ 上期；新进 / 跌出 / "—"规则；表注四要素（占比口径 / 对比基准 / 已披露数据 / 明细去向）
- C8-2 表后 3—4 点短加粗引导总结，含使用纪律一句
- C9-1 名词｜解释两列；以业务名词为主；估值专用词不收录（指向 `doc/估值理论/估值模型.md`）

## X 跨章一致性

- X1 全文一套色值（G2 的 hex 全文唯一）
- X2 同一阈值 / 口径跨章一致（抽查 2—3 个核心阈值在零 / 三 / 五 / 六章的表述）
- X3 术语与"九、名词解释"一致（如"机构口径 EPS"的用法与解释吻合）
- X4 除 §一.5 豁免处与八章表外，无任何"最新一期"季度数字；基线时点数据有日期标注
- X5 文内路径可解析（项目根相对路径核对文件存在性）

## D 数字自洽（本地复核，不需要外部请求；锚：主报告规范 §二、估值纪律）

- D1 分部占比加总 = 100%；分部收入加总 = 总收入
- D2 抽 5—8 个同比 / 比率 / 占比复算
- D3 护城河加权算式复算 = 总分结论
- D4 净现比 = 经营现金流 ÷ 归母净利复算
- D5 情景表：按报告声称的参数重跑 `node tools/valuation.js <spec.json>`，逐格比对（内在 PE / 股价 / 相对现价）
- D6 EPS × 股本 ≈ 净利 的口径自洽（口径差须有解释，参照口径卡）
- D7 机构预测 EPS / PE 与 `api/orgForecast.js` 一致——**涉及外部请求，默认不执行**，由主代理决定是否对源

## 附：校对子代理 prompt 模板

```text
你是独立校对代理，核对一份已完成的研报是否符合研报模板规范。

输入：
- 报告文件：<路径>
- 清单：doc/研报/研报模板/成稿自检清单.md（本文）
- 规范：doc/研报/研报模板/主报告规范.md + 同目录 README.md（格式细则）
- 口径卡：<doc/知识库/公司/<公司>/口径卡.md 路径，或"无">

任务：逐组执行清单 G / H / C / X / D，每条输出：结果（✅/⚠️/❌）、
位置（章节 + 行引用或原文片段，违规必给）、一句修正建议。

硬约束：
1. 只核对，不修改任何文件——修改决定权在主代理；
2. 禁止联网、禁止调用外部数据接口；数字复核只用本地计算与报告/口径卡
   内的参数（D5 例外：允许运行 node tools/valuation.js 复跑情景表）；
3. 不评价主观判断质量（归因、假设、观点），只查清单内的可机械判定项；
4. 全部条目过完再输出：先给"违规清单表"（❌/⚠️，附编号与位置），
   再给逐条明细。
```
