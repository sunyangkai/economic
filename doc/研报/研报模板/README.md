# 研报模板 · README（通用规范）

> **本文件是 [主报告规范.md](主报告规范.md)、[财报跟踪规范.md](财报跟踪规范.md) 与 [行业研究框架.md](行业研究框架.md) 的索引 + 共用规则**：模板各管什么、文件夹结构、相对路径、数据与工具纪律、分工纪律、格式与排版。

## 一、文件结构

### 1.1 公司研报文件夹（推荐形态）

```
doc/研报/公司/<公司>/
├── <公司>.md              # 主报告：分析框架 + 财务基线（最新年报），不随季度改写
└── 财报跟踪/
    ├── 2026一季报.md       # 每报告期一个文件（实例层），格式见财报跟踪规范
    ├── 2026中报.md
    └── 2026三季报.md       # 未披露时为"模板/待披露"
```

### 1.2 模板文档（本文档所在文件夹）

```
doc/研报/研报模板/
├── README.md              # 本文：模板索引 + 共用规则
├── 主报告规范.md           # 公司主报告长什么样（分析框架 + 基线 + 研究流程）
├── 财报跟踪规范.md         # 公司财报跟踪文档长什么样（按框架逐期更新）
└── 行业研究框架.md         # 行业研报长什么样（行业版框架 + 基线 + 跟踪）
```

### 1.3 公司文件夹的内容组织（不设 README）

公司文件夹**不设 README.md**，原 README 承载的目录信息改由主报告头部承载：

- **文件组织**：公司文件夹 = 主报告（`<公司>.md`）+ `财报跟踪/`（每报告期一个文件），无其他文件；

- **拆分约定**：主报告 = 分析框架 + 财务基线（最新年报），不随季度改写；财报跟踪 = 实例层，每期新建对应文件逐期更新——见主报告规范"一、定位与更新纪律"与财报跟踪规范"一、定位与纪律"；

- **下一披露节点**：写在主报告头部（"下一报告期将于 <日期> 披露"）——见本文档"6.1 报告头部格式"；

- **跟踪文件状态**（已披露 / 待披露）：由主报告头部的跟踪链接标注（如 `[2026 中报（待披露）](...)`）。

### 1.4 行业研报文件夹结构

行业报告默认**单文件**存放于 `doc/行业/<行业>.md`（行业更新频率低、事件驱动）；数据密集、月度跟踪成为常态时升级为文件夹结构（升级规则见 [行业研究框架.md](行业研究框架.md)"九、跟踪清单"）：

```
doc/行业/<行业>/
├── <行业>.md              # 行业主报告：行业分析框架 + 行业基线（不随事件改写）
└── 跟踪/
    ├── 2026-07.md          # 月度景气跟踪（或按事件命名：<事件>.md）
    └── ...
```

## 三、数据与工具纪律

| 用途 | 工具 | 说明 |
| --- | --- | --- |
| 财务数据（三表/主要指标） | `api/mainFinanceData.js`、`api/balanceSheet.js`、`api/incomeStatement.js`、`api/cashFlowStatement.js` | 走东方财富 F10 封装 |
| 行情 | `api/quote.js`（`getQuote`） | 腾讯接口，单/批量，GBK 自动解码 |
| 股东结构 | `api/holderData.js`（`getHolderNumberTrend` / `getTopFreeHolders` / `getTopHolders`） | 户数 + 前十大流通股东逐期对比 |
| 机构一致预期 | `api/orgForecast.js`（`getOrgForecast`） | 近六月平均 + 各机构 EPS |
| 公司大事/增减持/质押 | `api/companyEvents.js` | |
| **估值计算** | **`tools/valuation.js`** | `--help` 看用法；`<spec.json>` 输出 markdown 情景表 |
| **官方 PDF → 文本** | **`tools/pdf2text.js`** | 官方年报/中报 PDF 提取原文（管理层讨论/分部明细/经营计划/风险/分红原文） |
| 临时脚本 | `temp/` | 用完即删，不提交 |

边界：`api/` = 数据获取（外部数据源），`tools/` = 计算与工具函数，不要把估值计算写进 `api/`，不要绕过 `api/` 自行拼接外部请求。

**行业数据纪律**：公司报告三件套的数据纪律同样适用于行业报告；行业特有的补充（代表公司聚合口径、行业统计口径差异、政策原文优先）见 [行业研究框架.md](行业研究框架.md)"四、数据与工具纪律（行业版）"。

**数据来源纪律（分层优先级）**：

1. **硬财务数字**（三表/指标/股东/一致预期）→ `api/` 工具（结构化、快、准）；

2. **叙述性内容**（管理层讨论与分析、分部明细、经营计划、风险提示、分红原文）→ **官方报告 PDF 优先**（存 `doc/研报/公司/定期报告原文件/<公司>/`，用 `tools/pdf2text.js` 提取）；

3. **网络搜索只在上述两者无法覆盖时使用**——例如券商观点、行业动态、政策文件、地缘与诉讼进展。网络获取的信息**须注明来源与日期**。

**分析观点纪律（优先级高于一切二手分析）**：

- **任何分析观点（管理层观点、增长方向判断、风险判断、估值假设）以财报/官方报告原文为基准**——官方文件（年报/中报/季报、业绩说明会纪要、公告）是一手依据；

- **券商研报、媒体点评等二手分析只作参考与交叉验证**，用于补充官方未披露的信息或提供市场视角，**不作为观点基准**；

- 官方与二手分析冲突时，**以官方为准**，并在报告中说明差异（如"券商一致预期隐含 H2 +76%，官方口径未给出指引，按保守侧处理"）；

- 引用二手分析须注明来源与日期，避免把"别人怎么说"写成"事实"。

## 四、分工纪律

1. **公司主报告（框架层）**：怎么分析、看什么、阈值多少——低频更新（年报重锚 / 逻辑与阈值变化即时）；季报不动。

2. **公司财报跟踪（实例层）**：框架变量的逐期实绩与验证——每期更新；不发明新变量；发现缺口先改主报告。

3. **行业报告（行业层）**：行业判断 + 公司分层 + 受益排序；个股财务 / 估值 / 治理 / 筹码一律在公司报告，行业报告不重复展开（详见 [行业研究框架.md](行业研究框架.md)）。

4. **模板（元层）**：规定以上各层长什么样——格式问题改这里，不逐个改主报告。

5. 实绩数据只出现在跟踪层（`财报跟踪/` 或行业跟踪清单）；主报告出现任何"最新一期"数字即违反分工（基线时点数据除外，须标注基线日期）。

## 五、格式与排版

- **列表分点**：分点列表（`-`、`① ② ③`、编号等）的条目之间**留空行**，每条独立成段，不要挤在一起——分点拥挤时长句连成一片，难以逐条扫读。此规则适用于正文、表格附注、指引说明等所有分点场景。

- **表格中短分类列撑宽**：只有一两个字、整列内容很短且可能被相邻长列挤压的列（如风险"评级"列：高 / 中高 / 中 / 中低），渲染时会显得拥挤——给该列每个单元格包一层内联样式撑宽并居中：`<span style="display:inline-block;min-width:3.2em;text-align:center">高</span>`（宽度按实际调整）；HTML 不可用时退而求其次，用 Markdown 对齐标记让该列居中（`:---:`）。

- **符号着色（通用）**：所有带 + / − 符号的数值（同比、增速、涨跌幅、增减额等）按 A 股惯例着色：**+ 红、- 绿**，颜色仅为渲染标注、不代表利好利空判断（实现用 HTML 内联 `<span style="color:#d02020">+…</span>` / `<span style="color:#0f7a33">-…</span>`；纯文本环境不渲染颜色时 ± 号本身仍可读）。同一报告内色值统一。

- **数据表通用呈现**：①数值列只放纯数字、右对齐、加千分位；②同比类变化**独立成列**（或紧随数值），内容只写"± 数字 + 单位"（金额/数量用 %，比率用 pp，周转天数用天，负值净额科目用增减额），**不写"同比增长 / 净流出扩大"等文字**；③短分类列撑宽见上条；④表题三要素：**期数、单位、口径说明**（如"（2024—2025，单位：亿元；'同比' = 2025 较 2024）"）；⑤自算科目在项目名标注"（自算）"；⑥解读列文字不着色。

- **解读入表**：数据表的解读与行一一对应，放在表内末列"解读"（跨多行的归因贴在被解释行）；整表层面的判断用表后一句"**这张表告诉我们……**"，不再在表外另起"解读：××"分点段落。

- **章节内小节编号**：正文章节内的小节标题用 `### 1. / 2. …` 编号。

## 六、主报告版式规则（纯格式：头部模板、表格细则与成稿样板。通用排版见"五、格式与排版"；各章写什么、章节结构与职责见 [主报告规范.md](主报告规范.md)）

### 6.1 报告头部格式

```markdown
# <公司>（<代码>.SZ）

> **独立研究报告**（写作基准：<YYYY-MM-DD>；财务基线：<YYYY> 年报 + 截至基线的快照；下一披露节点：<报告期>，约 <日期>；后续实绩见 [`财报跟踪/`](财报跟踪/) 目录，每报告期一个文件）：
> [2026 一季报跟踪](财报跟踪/2026一季报.md)｜[2026 中报（待披露）](财报跟踪/2026中报.md)｜[2026 三季报（待披露）](财报跟踪/2026三季报.md)

> 报告更新：<YYYY-MM-DD>（A 股现价 <X> 元，<日期> <盘中/收盘>）。数据来源：东方财富 F10 财务接口（api/）、机构盈利预测接口（api/orgForecast.js，<日期> 一致预期）、股东户数与前十大流通股东接口；估值计算用 tools/valuation.js（统一三段式模型）。财务基线为 <YYYY> 年报，此后实绩更新见 `财报跟踪/`。
```

要点（纯版式；头部"写什么"的内容要求见 主报告规范 §一.3）：①头部为两个引用块——第一块元信息（基准日 / 基线年报 / 下一披露节点 / 跟踪链接），第二块报告更新行（现价 + 数据来源）；②基线一律写"<YYYY> 年报"；③现价必须带日期与"盘中 / 收盘"口径；④跟踪链接用全角"｜"分隔、括号标注状态（已披露 / 待披露 / 待补建；不回补的历史期不列，判定规则见 主报告规范 §一.4）。

### 6.2 三、财务报表分析：表格细则与成稿样板

- 每个小节先放一张**要点表**，表题注明期数与单位（如"利润表要点（2024—2025，单位：亿元；'同比' = 2025 较 2024）"）；表下**不再另起"解读：××"分点段落**——**解读并入表内：末列设"解读"，与每行一一对应**；跨多行的归因贴在被解释的那一行（如毛利率行的归因拆解），整表层面的判断由表后一句"**这张表告诉我们**……"收口。

- 数值列之间加一列**"同比"**（与上一可比期比较）：数值列只放纯数字、右对齐、**不加括号**；同比列只放**符号 + 数字**（如 +17.0% / +1.8pp / +19.7 天 / -456 亿），**不写括号、不写"净流出扩大""同比增长"等文字**。

- 同比口径：金额 / 数量类用 %；比率类（毛利率、净利率、实际税率、资产负债率等）用**百分点 pp**；周转天数类用天；**负值科目**（财务费用净额、投资 / 筹资活动净额等净额类）与净现比等**用净额增减**（亿元 / 数值，不强行算 %），章首注可说明"负 = 净流出扩大 / 净收益收窄、正 = 收窄 / 扩大"。

- **着色按 A 股惯例只表示增减符号：+ 红、- 绿**，不代表利好利空判断（实现用 HTML 内联 `<span style="color:…">`；纯文本环境不渲染颜色时 ± 号本身仍可读）。

- 列示期数不必贪多：**以能讲清趋势为准，通常基线年报 + 前 1—2 年（共 2—3 列）**；起始列无上一期可比、不标同比。

- **成稿样板（三章报表表照此格式落成；表中数字仅为格式示意，非真实值）**：

  ```
  **利润表要点（2024—2025，单位：亿元；"同比" = 2025 较 2024，"解读"与每行一一对应）**

  | 项目 | 2024 | 2025 | 同比 | 解读 |
  | --- | ---: | ---: | ---: | --- |
  | 营业总收入 | 3,620.1 | 4,237.0 | +17.0% | 量增价降——本行的"数字背后是什么"（每行一句） |
  | 毛利率 | 24.4% | 26.3% | +1.8pp | 归因拆解贴在本行（①电池主业走平 ②回收修复 ③境外结构） |
  | 财务费用（净额，负 = 净收益） | -41.3 | -79.4 | +38.1 亿 | 净收益口径说明（负值科目用净额增减） |
  | 归母净利润 | 507.4 | 722.0 | +42.3% | 全篇盈利基准，标"**"加粗 |
  | 归母净利率（自算） | 14.0% | 17.0% | +3.0pp | 自算科目在项目名标注"（自算）" |

  **这张表告诉我们**：整表层面的一句话判断（逐行解读已在"解读"列，这里只讲结论）。
  ```

  配套要求：①表题三要素齐全——期数、单位、口径说明（如"'同比' = 2025 较 2024"）；②数值列纯数字、右对齐、加千分位，不加括号；③"同比"列渲染时按符号着色（+ 红、- 绿），文字内不写"同比增长 / 净流出扩大"等；④若需再往前列一年（如加 2023 列），插在"2024"前即可，起始列（2023）不标同比，其余规则不变；⑤"经营/产销/人员"类数据表同用这套五列（指标 | 上期 | 本期 | 同比 | 解读）或独立"同比"列样式，规则一致；⑥每张要点表后配一句"这张表告诉我们……"的整表判断，逐行解读已在表内完成，表后只讲整表结论。
