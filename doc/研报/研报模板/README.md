# 研报模板 · README（通用规范）

> **本文件是 [主报告规范.md](主报告规范.md) 与 [财报跟踪规范.md](财报跟踪规范.md) 的索引 + 共用规则**：三件套各管什么、文件夹结构、相对路径、数据与工具纪律、分工纪律、格式与排版。

## 一、文件结构

### 1.1 公司研报文件夹（推荐形态）

```
doc/研报/公司/<公司>/
├── <公司>.md              # 主报告：分析框架 + 财务基线（最新年报），不随季度改写
└── 财报跟踪/
    ├── 2026一季报.md       # 每报告期一个文件（实例层），格式见财报跟踪规范
    ├── 2026中报.md
    └── 2026三季报.md       # 未披露时为"模板/待披露"
```

### 1.2 模板文档（本文档所在文件夹）

```
doc/研报/研报模板/
├── README.md              # 本文：三件套索引 + 共用规则
├── 主报告规范.md           # 主报告长什么样（分析框架 + 基线）
└── 财报跟踪规范.md         # 跟踪文档长什么样（按框架逐期更新）
```

### 1.3 公司文件夹的内容组织（不设 README）

公司文件夹**不设 README.md**，原 README 承载的目录信息改由主报告头部承载：

- **文件组织**：公司文件夹 = 主报告（`<公司>.md`）+ `财报跟踪/`（每报告期一个文件），无其他文件；
- **拆分约定**：主报告 = 分析框架 + 财务基线（最新年报），不随季度改写；财报跟踪 = 实例层，每期新建对应文件逐期更新——见主报告规范"一、定位与更新纪律"与财报跟踪规范"一、定位与纪律"；
- **下一披露节点**：写在主报告头部（"下一报告期将于 <日期> 披露"）——见主报告规范"二、头部格式"；
- **跟踪文件状态**（已披露 / 待披露）：由主报告头部的跟踪链接标注（如 `[2026 中报（待披露）](...)`）。

## 三、数据与工具纪律

| 用途 | 工具 | 说明 |
| --- | --- | --- |
| 财务数据（三表/主要指标） | `api/mainFinanceData.js`、`api/balanceSheet.js`、`api/incomeStatement.js`、`api/cashFlowStatement.js` | 走东方财富 F10 封装 |
| 行情 | `api/quote.js`（`getQuote`） | 腾讯接口，单/批量，GBK 自动解码 |
| 股东结构 | `api/holderData.js`（`getHolderNumberTrend` / `getTopFreeHolders` / `getTopHolders`） | 户数 + 前十大流通股东逐期对比 |
| 机构一致预期 | `api/orgForecast.js`（`getOrgForecast`） | 近六月平均 + 各机构 EPS |
| 公司大事/增减持/质押 | `api/companyEvents.js` | |
| **估值计算** | **`tools/valuation.js`** | `--help` 看用法；`<spec.json>` 输出 markdown 情景表 |
| **官方 PDF → 文本** | **`tools/pdf2text.js`** | 官方年报/中报 PDF 提取原文（管理层讨论/分部明细/经营计划/风险/分红原文） |
| 临时脚本 | `temp/` | 用完即删，不提交 |

边界：`api/` = 数据获取（外部数据源），`tools/` = 计算与工具函数，不要把估值计算写进 `api/`，不要绕过 `api/` 自行拼接外部请求。

**数据来源纪律（分层优先级）**：
1. **硬财务数字**（三表/指标/股东/一致预期）→ `api/` 工具（结构化、快、准）；
2. **叙述性内容**（管理层讨论与分析、分部明细、经营计划、风险提示、分红原文）→ **官方报告 PDF 优先**（存 `doc/研报/公司/定期报告原文件/<公司>/`，用 `tools/pdf2text.js` 提取）；
3. **网络搜索只在上述两者无法覆盖时使用**——例如券商观点、行业动态、政策文件、地缘与诉讼进展。网络获取的信息**须注明来源与日期**。

**分析观点纪律（优先级高于一切二手分析）**：
- **任何分析观点（管理层观点、增长方向判断、风险判断、估值假设）以财报/官方报告原文为基准**——官方文件（年报/中报/季报、业绩说明会纪要、公告）是一手依据；
- **券商研报、媒体点评等二手分析只作参考与交叉验证**，用于补充官方未披露的信息或提供市场视角，**不作为观点基准**；
- 官方与二手分析冲突时，**以官方为准**，并在报告中说明差异（如"券商一致预期隐含 H2 +76%，官方口径未给出指引，按保守侧处理"）；
- 引用二手分析须注明来源与日期，避免把"别人怎么说"写成"事实"。

## 四、三件套分工纪律

1. **主报告（框架层）**：怎么分析、看什么、阈值多少——低频更新（年报重锚 / 逻辑与阈值变化即时）；季报不动。
2. **财报跟踪（实例层）**：框架变量的逐期实绩与验证——每期更新；不发明新变量；发现缺口先改主报告。
3. **模板三件套（元层）**：规定前两层长什么样——格式问题改这里，不逐个改主报告。
4. 实绩数据只出现在 `财报跟踪/`；主报告出现任何"最新一期"数字即违反分工（基线时点数据除外，须标注基线日期）。

## 五、格式与排版

- **列表分点**：分点列表（`-`、`① ② ③`、编号等）的条目之间**留空行**，每条独立成段，不要挤在一起——分点拥挤时长句连成一片，难以逐条扫读。此规则适用于正文、表格附注、指引说明等所有分点场景。
