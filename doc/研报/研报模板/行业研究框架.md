# 行业研究框架（行业研报模板）

> **行业报告 = 行业分析框架 + 行业基线**：回答"这个行业怎么分析、景气朝哪走、利润在产业链哪里赚、哪些公司受益、判断如何被证伪"；数据底座以**行业基线**（最新完整年度数据 + 最新景气快照）为锚点，后续验证进跟踪清单，主报告不随事件改写。
>
> 本文件是公司研报三件套（[README.md](README.md) / [主报告规范.md](主报告规范.md) / [财报跟踪规范.md](财报跟踪规范.md)）的**行业扩展**：**共用 README 的路径、数据与工具、分工、格式规则**，本文只规定行业报告与公司报告不同的部分。行业报告默认存放于 `doc/知识库/行业/<行业>.md`（路径约定见 README"二、路径与引用规范"）。

## 一、定位与更新纪律

| 项 | 规则 |
| --- | --- |
| 本质 | **行业分析框架**（怎么分析、看什么、阈值多少）+ **行业基线**（最新完整年度数据 + 最新景气快照） |
| 基线 | 以**最新完整年度数据**为财务/景气基线（如 2025 年报季聚合），头部明确标注基线时点；月度/季度高频数据作为"最新景气快照"单独标注日期 |
| 更新触发 | ① **年度重锚**：年度数据齐全后刷新基线；② **框架修订**：行业逻辑、景气方向、政策框架、估值基准变化时即时修订；③ **常规事件不进主报告**——月度数据、政策文件、批次事件全部进跟踪清单 |
| 与公司报告分工 | 行业报告给**行业判断 + 公司分层 + 受益排序**；个股财务、个股估值、治理、筹码一律在公司报告（`doc/研报/公司/<公司>/`），行业报告不重复展开 |

**核心纪律：行业报告管"行业"，不管"个股"。** 行业报告里出现个股逐季财务细节即属越界；个股结论以公司报告为准，行业报告只给"这家公司在行业逻辑里的位置"。

行业报告与公司报告的分工表：

| 内容 | 行业报告 | 公司报告 |
| --- | --- | --- |
| 行业定义、产业链、需求空间、竞争格局、政策 | ✓ | 引用行业报告，不重写 |
| 景气判断、行业增速 [g1,g2,g3] | ✓ | 作为"二、宏观背景"的输入 |
| 公司分层与受益排序 | ✓（只给排序与受益逻辑） | 个股逻辑展开 |
| 个股财务基线、个股估值、治理、筹码 | ✗ | ✓ |
| 行业数据验证 / 个股季报验证 | ✓（跟踪清单） | ✓（财报跟踪） |

## 二、头部格式

```markdown
# <行业>行业研究报告

> **独立行业研究**（写作基准：<YYYY-MM-DD>；行业基线：<YYYY> 完整年度数据 + <YYYY-MM> 最新景气快照；覆盖范围：<地域 / 细分范围>；下一数据节点：<行业数据 / 政策节点>，约 <日期>；遵循 `doc/研报/研报模板/行业研究框架.md`）
>
> 相关公司报告：`doc/研报/公司/<公司A>/<公司A>.md`｜`doc/研报/公司/<公司B>/<公司B>.md`
>
> 报告更新：<YYYY-MM-DD>。数据来源：<行业官方来源，注明文件与日期>、代表公司公告（经 api/ 接口）；行业统计口径差异见"四、数据与工具纪律"。行业基线为 <YYYY> 年度，此后验证见"九、跟踪清单"。
```

要点：

- 基线明确写"<YYYY> 完整年度数据 + 最新景气快照时点"，快照日期单独标注——行业数据更新频率不一，混在一起会失去时效感。

- **覆盖范围必须写**：地域 / 细分口径不同，行业规模与结论完全不同（如"中国创新药"与"全球创新药"是两个行业）。

- 相关公司报告链接放头部，作为行业 → 公司的导航；公司清单与分层逻辑放"八、估值与投资框架"。

- 行业数据发布是事件驱动，写明"下一数据节点"（如医保谈判时间、行业统计年鉴发布、集采批次），作为头部与跟踪清单的桥。

## 三、章节骨架

### 章节速览

| 章节 | 一句话目的 |
| --- | --- |
| 零、核心逻辑 | 全篇的纲：行业阶段判断 + 景气方向 + 产业链利润分配 + 可证伪的验证指标 + 投资主线 |
| 一、行业定义与产业链地图 | 行业是什么、边界在哪、产业链各环节与利润分配（客观描述，不下判断） |
| 二、需求分析 | 钱从哪来：需求驱动、量价拆分、空间测算（TAM / SAM / SOM） |
| 三、供给与竞争格局 | 谁在供给、格局如何、壁垒与出清逻辑 |
| 四、政策与监管 | 政策框架、周期位置、对需求/供给/估值的影响路径 |
| 五、技术与产品迭代（可选） | 技术路线与迭代周期、颠覆风险（不适用时并入一 / 三） |
| 六、行业财务与景气度（基线） | 行业整体财务画像 + 景气指标体系 + 阈值（年度重锚） |
| 七、景气展望（基准情景） | 输出行业基准路径 [g1,g2,g3] + 增长驱动拆分 + 关键假设 |
| 八、估值与投资框架 | 行业估值水位 + 各环节/各层公司估值方法 + 公司分层受益排序 |
| 九、跟踪清单 | 数据日历 + 景气验证指标与阈值 + 风险清单（唯一变量来源） |
| 十、备注：名词解释 | 行业名词一览表，读者无需外部资料 |

> 行业报告固定十一章（零~十），各章独立成节。**五（技术迭代）为可选章**：不适用时并入"一、行业定义"或"三、供给与竞争格局"，其余章节号保持不变（缺章注明"本章不适用"）。具体取舍按行业情况自定，不必逐条照搬。

### 零、核心逻辑

全篇的"纲"。本章只做结论性判断，不展开数据论证；每个判断在后续章节都有对应证据，读者读完本章即掌握全文骨架。

**开篇以"要点速览"小结引导（本章第一小节）**：把行业判断压成**可证伪**的要点——行业处于什么阶段、景气朝哪个方向、利润在产业链哪里赚、投资主线选什么，**不要写超长的"一段话核心逻辑"堆叠段**。写法：

- **小节标题**：`### 要点速览`（与章内其他小节同级）；
- **第一段（结论要点）**：阶段 / 景气方向 / 利润分配 / 投资主线每类各一句直接下结论，数字只给锚点，论证留给后续小节；
- **第二段（统计口径提醒，按需）**：存在读前必须先知道的统计口径差异（如行业销售口径多版本、样本范围）时，用自然引导另起一段（如"先记一个统计口径：……"），不堆进结论段；
- **段落收尾**：一句导航（证据链见以下各节，跟踪清单见对应章节）。

**建议结构**（要点速览之后）：

- **行业阶段判断**：导入期 / 成长期 / 成熟期 / 衰退期，判断依据（渗透率、增速拐点、格局集中度）——不同阶段的投资范式完全不同（成长期看渗透率与格局，成熟期看份额与现金流）。

- **景气方向**：未来 1—3 年行业整体增速方向与量级，按需求 / 供给 / 政策三条线各给一个判断，每个方向写四件套：
  - **逻辑**：为什么这个方向能带来增长（一句话本质）；
  - **驱动力**：现实里哪些因素正在推动（列 2—3 条，写清"政策 / 技术 / 需求 / 出海"的具体机制，不堆概念）；
  - **验证指标**：看什么指标、阈值多少、跟踪频率与来源——行业版的"仪表盘"，**不过期**；
  - **现实约束**：什么条件下它会证伪——**必写**，防止只讲乐观面。

- **产业链利润分配**：利润在往哪个环节移动（上游资源 / 中游制造 / 下游品牌渠道 / 卖水人），分配移动的驱动是什么。

- **投资主线**：从行业判断落到"买哪类公司"——龙头（确定性）/ 弹性标的（贝塔放大）/ 产业链配套（卖水人），每条指向"八、估值与投资框架"的分层。

### 一、行业定义与产业链地图

**客观描述**：行业是什么、钱从哪来、产业链怎么分工。**不下判断**，判断留给"零、核心逻辑"。

**建议结构**：行业定义与边界 → 产业链地图 → 各环节价值量与利润分配（结构层面，不写个股经营数字）→ 行业特点。

- **行业定义与边界**：按什么口径定义（产品 / 技术 / 政策许可）、包含哪些细分、排除哪些相邻行业；**口径写清楚**——不同统计口径下"行业规模"差异巨大，全篇数据必须与定义一致。

- **产业链地图**：上游（原材料 / 设备 / 技术供给）→ 中游（制造 / 服务）→ 下游（渠道 / 终端应用）→ 支付方（终端用户 / 医保 / 财政 / 企业客户）。每个环节写清"这个环节提供什么、与上下游的分工边界在哪"。

- **各环节价值量与利润分配**：各环节附加值水平、利润分配格局（结构层面，如产能门槛、市占率格局），为"零、核心逻辑"的利润分配判断提供地图；不写具体公司的收入 / 增速 / 毛利率等经营数字。

- **行业特点**：提炼行业的**结构性**特点（重资产 / 轻资产、强周期 / 弱周期、技术驱动 / 渠道驱动、政策敏感度），为后续章节埋伏笔。

### 二、需求分析

回答"钱从哪里来、往哪里扩、总量多大"。行业需求是景气判断的根基。

**建议结构**：需求驱动拆解 → 量价拆分 → 空间测算 → 需求预测方法。

- **需求驱动拆解**：终端需求来自哪几类（人口与渗透、技术替代、政策拉动、出口 / 出海），每类写清机制与可持续性——内生结构性 / 政策一次性 / 低基数修复三者的可持续性天差地别，必须拆开看。

- **量价拆分**：量 = 渗透率 × 使用频次 / 用量；价 = 定价能力 / 集采与降价 / 结构升级。**量价分开看**——很多行业"量增价跌"是常态，拆开才知道增长质量。

- **空间测算**：TAM（总量市场）→ SAM（可服务市场）→ SOM（可获取市场），给出测算口径与关键假设（渗透率终局、单价假设、对标成熟市场演进），**标出主观假设最强的变量**。

- **需求预测方法**：渗透率 S 曲线、对标成熟市场（如海外同行业渗透率演进）、人口 / 财富等长变量外推；说明不同方法的适用场景与误差来源。

### 三、供给与竞争格局

回答"谁在供给、格局好不好、壁垒在哪"。

**建议结构**：供给结构 → 竞争要素与壁垒 → 格局演进与出清逻辑。

- **供给结构**：玩家分层（龙头 / 二线 / 新进入者 / 跨界者）、产能与供给弹性、进入者来源（哪些行业跨界进来、进入门槛多高）。

- **竞争要素与壁垒**：技术 / 成本 / 渠道 / 品牌 / 资质牌照 / 规模，每个壁垒写清"**防的是谁** + 一句话本质 + 论证"——论证的关键是写出"这不是能力问题，是商业模式 / 组织能力 / 资源禀赋问题"式的本质差异。

- **格局演进**：集中度（CR3 / CR5）历史与当前、出清逻辑（价格战、并购整合、政策准入收紧）、格局变化对利润率的影响路径；给出集中度跟踪指标与来源。

### 四、政策与监管

行业研究中**最特殊的一章**——政策可以独立改变需求、供给和估值三个变量。

**建议结构**：监管框架 → 政策周期定位 → 影响路径与敏感性 → 政策跟踪节点。

- **监管框架**：准入（牌照 / 审批）、定价（指导价 / 集采 / 医保支付）、质量与安全标准、出口政策；每类政策写清"管什么、谁来管、文件层级"。

- **政策周期定位**：当前政策处于收紧 / 宽松 / 平稳的哪个阶段，近 3—5 年关键文件时间线，政策方向的历史脉络。

- **影响路径与敏感性**：政策 → 需求（补贴 / 支付 / 集采放量）、供给（准入 / 产能限制）、估值（政策风险溢价）；量化行业对政策的敏感度（如收入中政策相关占比）。

- **政策跟踪节点**：医保谈判、集采批次、审批动态、行业规划发布等，列入"九、跟踪清单"的数据日历。

- **宏观环境不单列一章**：利率 → 估值底座、汇率 → 出口竞争力、财政 / 医保支出 → 终端需求，宏观对行业的影响并入对应章节（需求 / 估值），但**传导路径必须写清**。

### 五、技术与产品迭代（可选）

技术驱动型行业（医药、电子、新能源）必写；周期 / 传统行业可不写。

**建议结构**：技术路线 → 迭代周期 → 当前阶段 → 颠覆风险。

- **技术路线**：当前主流技术路线与下一代路线的对比（性能 / 成本 / 成熟度）。

- **迭代周期**：技术迭代速度（产品生命周期长度），决定研发投入节奏与护城河更新时间。

- **当前阶段**：行业技术处于什么阶段（实验室 / 导入 / 放量 / 成熟），放量拐点的验证信号。

- **颠覆风险**：新技术对现有格局的颠覆路径与时间窗口——"现在赚钱的业务，3 年后还在吗"。

### 六、行业财务与景气度（行业基线）

从数字读出行业经营本质。本章 = **行业基线（最新完整年度数据）**，随**年度重锚**刷新，不随月度事件改写；高频数据在"九、跟踪清单"更新。

**建议结构**：

1. **行业整体财务画像**：收入规模与增速、利润率水平、资本开支强度、现金流特征——用**代表公司聚合**（选 3—5 家覆盖不同环节 / 规模的公司，用 `api/` 工具逐家拉数后聚合）或行业统计年鉴数据；**写明聚合口径**（哪些公司、权重方式、数据来源、时间范围）。
2. **景气度指标体系**：领先指标（订单、招标量、批文 / 注册、渠道库存）/ 同步指标（产量、出货量、价格）/ 滞后指标（收入确认、利润率）；每个指标写清"看什么、阈值、来源、频率"。
3. **关键阈值**：列出需要逐期盯的科目与阈值（行业价格、库存周期位置、渗透率增速、政策相关收入占比），作为"九、跟踪清单"的基线参照。

**数据口径纪律**：行业统计数据来源多样（统计局 / 行业协会 / 第三方数据商），口径差异巨大，**每个数字必须标注来源与口径**；聚合用公司财务时注明"样本公司聚合，不代表全行业"。

### 七、景气展望（基准情景）

给出未来 1—3 年的行业基准、增长驱动、关键假设与可证伪指标。本章输出**行业基准路径 [g1,g2,g3]**——这是行业判断的核心输出，也是"八、估值与投资框架"的输入。

**建议结构**：业绩基准 → 增长驱动 → 关键假设与敏感性 → 情景对比。

- **业绩基准**：行业上年实际（基数，标注口径）+ 行业整体增速展望。

- **增长驱动**：按重要性列出未来几年的增长驱动，每条写清机制、量级贡献与验证指标。

- **关键假设与敏感性**：把增长驱动翻译成"未来三年行业增速从哪来、按什么口径拆"，**标出主观判断最强的一步与可证伪的跟踪指标**；做悲观 / 中性 / 乐观三档情景，每档写明触发条件。

- **情景对比**：三档情景下的行业增速与结构差异，帮助读者判断"市场当前定价的是哪一档"。

### 八、估值与投资框架

把行业判断翻译成"贵不贵、买哪类"。

**建议结构**：

1. **行业整体估值水位**：行业指数 PE / PB / PS 历史分位、当前所处位置、与历史中枢的偏离；注意周期行业用 PB、成长行业用 PE / PS 的适用性。
2. **各环节 / 各层公司估值方法**：成熟龙头用 PE / DCF，成长公司用 PS 或 PEG，管线 / 技术资产用 NPV 或分部估值；写明每个方法的适用条件与陷阱（如 PS 对利润率分化行业的失效）。
3. **公司分层与受益排序**：按"受益确定性 / 弹性 / 产业链配套"分层，每层给受益逻辑与代表公司；**个股估值计算在公司报告完成（统一 `tools/valuation.js`）**，行业报告只给排序与受益逻辑，不重复计算。
4. **配置时点框架**：行业 β 为主 vs 个股 α 为主的判断条件（景气上行初期 β 强、分化期 α 强）；什么阶段配龙头、什么阶段配弹性。

### 九、跟踪清单

定义跟踪什么（**写一次**）：数据日历、景气验证指标、风险验金石。本章是行业跟踪的**唯一变量来源**——跟踪只验证这里的项目，不发明新变量；最新状态按数据 / 事件节点滚动更新（更新方式见下），框架本身不随事件改写。

**建议结构**：数据日历（表）→ 景气验证指标（表）→ 风险清单（表）。

- **数据日历**：行业月度 / 季度数据发布（产量、价格、招标、批文）、政策节点（谈判、集采、规划）、技术事件（行业大会、审评动态），每项给"时间、内容、验证哪条逻辑"。

- **景气验证指标**：与"六"的指标体系一致——看什么指标、阈值、频率、来源。

- **风险清单**：按影响程度排序（高 → 低），每条写成"**如果发生什么 → 会造成什么后果**"，不写空话；风险是核心逻辑的逆命题。

**跟踪落地方式（二选一，按数据密度决定）**：

- **默认（单文件）**：`doc/知识库/行业/<行业>.md`；跟踪以本章每个指标的"最新状态"滚动更新，并标注日期。

- **升级（文件夹）**：行业数据密集、月度跟踪成为常态时，升级为文件夹结构，主报告头部同步改写跟踪链接：

```
doc/知识库/行业/<行业>/
├── <行业>.md              # 行业主报告：框架 + 基线（不随事件改写）
└── 跟踪/
    ├── 2026-07.md          # 月度景气跟踪（或按事件命名：<事件>.md）
    └── ...
```

行业名词、政策术语、缩写一览表（名词 | 解释），让读者无需外部资料就能读懂全篇。公司报告通用财务 / 估值术语不再重复（见公司 [主报告规范.md](主报告规范.md)"九、备注"）。

## 四、数据与工具纪律（行业版）

在 [README.md](README.md)"三、数据与工具纪律"之上，行业报告补充：

| 用途 | 工具 / 来源 | 说明 |
| --- | --- | --- |
| 代表公司财务（聚合基线） | `api/` 各模块 | 选覆盖不同环节 / 规模的公司，逐家拉数后聚合；注明口径 |
| 代表公司行情 / 一致预期 | `api/quote.js`、`api/orgForecast.js` | 用于"八"估值水位与预期对照 |
| 行业统计与政策数据 | **官方来源优先**：政府网站、行业协会、交易所 / 公司公告 | 网络搜索仅在官方无法覆盖时使用（券商观点、第三方数据、外媒），**须注明来源与日期** |
| 估值计算 | `tools/valuation.js` | 个股估值在公司报告使用；行业报告做整体情景时说明聚合口径 |

**数据来源纪律（分层优先级，同 README）**：

1. **硬数字**（公司财务 / 行情 / 一致预期）→ `api/` 工具（结构化、快、准）；
2. **行业与政策原文**（统计公报、政策文件、审批动态、公司公告）→ 官方来源，**原文优先**，注明文件名称与日期；
3. **网络搜索**只在上述两者无法覆盖时使用——券商行业观点、第三方行业数据、海外市场信息，**须注明来源与日期**。

**分析观点纪律（同 README）**：行业判断以官方数据与文件原文为基准；券商研报、媒体点评等二手分析只作参考与交叉验证，不作为观点基准；官方与二手冲突时以官方为准并说明差异。

**口径纪律（行业特有）**：行业规模 / 增速存在多重口径（如"创新药市场规模"有按销售额、按医保支出、按批文数等口径），全篇数据必须与"一、行业定义"的口径一致，换口径必须说明。
