## 三、目录约定

```
doc/研报/公司/<申万一级>/<申万二级>/<公司>/
├── <公司>.md              # 主报告（框架层，不随季度改写）
├── 财报跟踪/              # 实例层，每报告期一个文件
└── 定期报告原文件/         # 官方 PDF 原件 + pdf2text 提取的 .txt

doc/知识库/公司/<申万一级>/<申万二级>/<公司>/
└── 事实卡.md / 口径卡.md / 来源索引.md（稀疏，碰到哪家建哪家）
```

**一公司一目录**：原件随公司走、不单独成树——两棵树分离时已经出现过"有原件无报告"的漂移（原 `定期报告原文件/晶泰控股/`），合一后结构上不会再发生。

## 四、维护规则

1. **新增公司**：先定申万一级 / 二级 → 改 `doc/研报/industry-map.json` → 建三处目录 → 跑 `--check` 对齐 → `--index` 重生成本文件。

2. **申万调整分类 / 公司主业漂移**：**只改 map**，再跑 `--check`；目录搬迁按 map 机械执行，不在正文里手工找路径。

3. **引用一律写项目根相对路径**（形如 `doc/研报/公司/<一级>/<二级>/<公司>/<公司>.md`），不要把行业层省掉。

4. **定期巡检**：`node tools/swIndustry.js --check`——它同时扫描全库 markdown 的 `doc/` 路径文本是否存在，是链接腐烂的报警器。
