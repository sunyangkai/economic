# 投研工作区 · 入口

> AI 与协作者从这里开始。本项目 = A 股个股 / 行业研究的生产线：数据接口（`api/`）→ 知识库（`doc/知识库/`）→ 报告输出（`doc/研报/`），以方法层规范为合同；成稿验证是独立流程，仅在用户明确要求时执行（流程 E）。

## 路径约定（先读）

- **所有跨目录引用一律写项目根相对路径**（项目根 = 仓库根目录，如 `doc/知识库/宏观/`），**禁止 `../../../` 相对链**；同目录互链可直接写文件名。
- 跨目录路径在文档中以行内代码呈现（文本形式），由 AI / 读者按项目根解析，不依赖渲染器的相对跳转。

## 四层结构

```
L1 方法层   doc/研报/研报模板/（三件套 + 成稿自检清单）、doc/估值理论/   ← 怎么做（合同）
L2 领域知识 doc/知识库/宏观/ · 社会/ · 行业/                          ← 跨公司共享的事实与口径
L3 公司事实 doc/知识库/公司/<一级>/<二级>/<公司>/（事实卡 / 口径卡 / 来源索引）← 单公司事实底座
L4 输出层   doc/研报/公司/<一级>/<二级>/<公司>/                       ← 判断与结论
            ├── <公司>.md + 财报跟踪/                                 ← 主报告与逐期跟踪
            └── 定期报告原文件/（官方 PDF 原件 + .txt 提取件，随公司走）

            doc/研报/README.md         = 申万分类索引 + 覆盖地图
            doc/研报/industry-map.json = 行业归属唯一数据源（脚本与索引皆以此为准）

api/   = 数据获取层（东方财富等外部数据源封装）
tools/ = 纯计算层（valuation.js 估值 CLI、pdf2text.js PDF 提取、swIndustry.js 分类校验）

（`<一级>` / `<二级>` = 申万行业分类 2021 版的申万一级 / 二级行业名，目录只到二级）
```

**结构纪律**：①引用方向单一——报告引用知识库与方法层，知识库永不引用报告；知识 = 事实 + 口径 + 来源（无判断），判断只在输出层；②知识文件头部必须带 as-of 日期与来源，写报告发现知识过期 → **先改知识库、再写报告**；③公司事实卡碰到哪家建哪家，不批量补卡；④本文件只做路由，细节一律下沉到被指向的文件；⑤**公司落哪个行业目录只以 `doc/研报/industry-map.json` 为准**，路径与索引由 `tools/swIndustry.js` 对齐，不在正文里手工判断行业；⑥**一家公司 = 一个目录**（`<公司>.md` + `财报跟踪/` + `定期报告原文件/`），原件不单独成树。

## 任务路由

| 任务 | 流程 | 必读 |
| --- | --- | --- |
| 写新公司主报告 | 流程 A | `doc/研报/研报模板/主报告规范.md` |
| 财报跟踪（每报告期） | 流程 B | `doc/研报/研报模板/财报跟踪规范.md` |
| 行业报告 | 流程 C | `doc/研报/研报模板/行业研究框架.md` |
| 更新知识库（宏观月度 / 行业 / 公司卡） | 流程 D | 目标知识文件的状态头 |
| 算估值 / 提取官方 PDF | 直接用工具 | 一般公司：`doc/估值理论/估值模型.md`；**保险 / 综合金融集团：`doc/估值理论/保险公司估值.md`**；**银行：`doc/估值理论/银行估值.md`**（后两者均不适用三段式利润模型） |
| **成稿验证（独立流程，仅用户明确要求时执行）** | 流程 E | `doc/研报/研报模板/成稿自检清单.md` |

## 流程 A：写新公司主报告

1. **读规范**：主报告规范全文（§一 分工与更新纪律 / §二 研究流程 / §四 各章指引）。
2. **定行业归属**：查 `doc/研报/README.md` 分类索引确定申万一级 / 二级；新公司先跑 `node tools/swIndustry.js --new <公司>` 取三处目录路径，并把归属写入 `doc/研报/industry-map.json`——**分类只改 map，目录与索引由脚本对齐**（改完跑 `--check`）。
3. **Phase 0 前置定版**：时间轴、口径、数字核对表 → 落盘 `doc/知识库/公司/<一级>/<二级>/<公司>/口径卡.md`（无则先建）；核对并补建 `事实卡.md` 与 `来源索引.md`。
4. **硬数据**：`api/` 一次脚本抓齐（三表 / 主要指标 / 一致预期 / 股东）；官方 PDF → 存 `<公司>/定期报告原文件/` → `node tools/pdf2text.js <pdf> --out <txt>` → **主代理自己 grep** 关键段落（子代理禁止整读 PDF）。
5. **写作**：按主报告规范 §二 依赖顺序——半独立章素材齐可先写，主线 三→四→五→六 串行，零 / 九收口。
6. **估值**：情景表 `node tools/valuation.js <spec.json>` 生成，数字与 CLI 输出一致。
7. **交付**：写作完成即交付，**默认不做成稿验证**——用户明确要求"验证"时才走流程 E（独立验证流程，`doc/研报/研报模板/成稿自检清单.md`）。写作过程中的数字自检（Phase 0 数字核对表回查）不受影响。

## 流程 B：财报跟踪

读财报跟踪规范 → 只验证主报告六章定义的变量（不发明新变量）→ 三 / 五 / 六 / 八章完整列表更新（财务四表、估值两张情景表用 `tools/valuation.js` 重算、跟踪项逐项全列、流通股东三期对比表）→ 对照三章阈值。成稿数据验证默认不执行，用户明确要求时走流程 E。
跟踪层**只建"最新已披露报告期"，历史不回补**（主报告规范 §一.4）。

## 流程 C：行业报告

按行业研究框架（头部 / 基线 / 跟踪清单）执行，报告与行业知识同放 `doc/知识库/行业/`。

## 流程 D：更新知识库

宏观月度（`doc/知识库/宏观/`）、行业景气（`doc/知识库/行业/`）、公司事实卡（随年报重锚与重大公告）——每次更新刷新状态头（as-of / 来源 / 下次更新触发），并检查引用该知识的报告是否需要框架修订。

## 流程 E：成稿验证（独立流程，仅用户明确要求时执行）

用户说"验证 / 校对 / 过一遍自检清单"时才执行。读 `doc/研报/研报模板/成稿自检清单.md` → 只校数据（数字自洽 + 跨章数据一致），不校格式 / 排版 / 章节结构 → 可派独立校对子代理（prompt 模板附于清单文末），❌ 清零后回报。流程 A / B 交付不触发本流程。

- 2026-09-10：**新增 `doc/估值理论/银行估值.md`**——商业银行**不再套用**三段式利润模型，改用 **P/B—ROE 相对估值锚 + 剩余收益（RIM）**。理由：利润被拨备计提调节（可被"蓄水池"平滑）、增长受资本充足率约束（`g = ROE × 留存率`）、净资产是估值分母而非"不参与估值"项。核心论点：**`P/B = 1` 等价于 `ROE = r`（与 g 无关）**，故破净的本质是市场认为可持续 ROE 将长期低于股权要求回报率；行业实际 ROE 7.72%（2026H1 监管口径）vs 统一 `r` 7.3% 仅差 0.42pct，而市场 P/B 长期 0.5—0.8 倍——**这一背离就是银行估值全部分歧所在**，文档用"隐含可持续 ROE / 隐含股权成本"两种读法把它量化，并明确**统一 R 在银行上只作一致性标尺、不直接生成目标价**。路由已同步：根 README 任务路由、`主报告规范.md` §五（行业例外改为保险 / 银行两条）、`研报模板/README.md` §二、`AGENTS.md` 估值条目。
